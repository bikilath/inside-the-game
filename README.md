# Inside the Game — Synthetic Match Insights Engine

Submission for the **Inside the Game: Developer Hackathon** (Microsoft × Premier League).

Turns synthetic, football-realistic event data into explainable match intelligence:
real-time statistics, momentum states, ranked key moments, and the structured
inputs a narrative layer needs to explain *why* a moment mattered.

> **Data statement:** all data in this repository is **synthetic**, generated by
> `src/match_sim.py`. No real Premier League match data is used, included, or
> redistributed. Club and player names are fictional.

---

## Pipeline

The challenge brief defines one pipeline with five stages. This repository
currently covers the first two, with the remaining three scaffolded:

| Stage | Brief | Status | Where |
|---|---|---|---|
| (a) Ingest | Consume synthetic match events as they happen | Done | `src/match_sim.py` (`--stream`) |
| (b) Interpret | Aggregate into football states and statistics | Done | `src/analyze.py` |
| (c) Explain | Say why a moment matters | Partial — key-moment ranking + control/chaos states | `src/analyze.py` |
| (d) Render | Put insight on screen alongside the match | To build | — |
| (e) Personalize | Analyst vs casual fan, club/player focus, language | To build | — |

## Quick start

```bash
# 1. generate a match (deterministic with --seed)
python3 src/match_sim.py --out data/match.jsonl --seed 7

# 2. analyze it
python3 src/analyze.py data/match.jsonl

# 3. write the full machine-readable report
python3 src/analyze.py data/match.jsonl --json reports/report.json
```

Replay a match in near-real-time, which is how the live pipeline is driven:

```bash
python3 src/match_sim.py --out data/live.jsonl --stream --speed 60
```

`--speed 60` plays 60 seconds of match time per wall-clock second. Use
`--speed 1` for true real time.

No third-party dependencies — the generator and analysis layer are pure Python 3.10+.

## The event model

`match_sim.py` emits newline-delimited JSON (one event per line). Every event
carries `event_id`, `match_id`, `sequence`, `period`, `clock_s`, `clock`,
`type`, `team_id`, `player_id`, `player_name`, and the running `score`.

| Event type | Notable fields |
|---|---|
| `pass` | `start`/`end` coordinates, `distance_m`, `progressive_m`, `is_progressive`, `difficulty` (0–1), `ball_speed_ms`, `pressure`, `outcome` |
| `carry` | `start`/`end`, `distance_m`, `duration_s`, `top_speed_ms`, `pressure` |
| `shot` | `location`, `distance_m`, `xg`, `shot_speed_ms`, `body_part`, `pressure`, `outcome` |
| `tackle`, `interception`, `duel_lost`, `foul` | `location`, `opponent_id`, `pressure`, `outcome` |
| `pressure` | `location`, `intensity`, `players_committed`, `target_team` |
| `possession_change` | `from_team`, `to_team`, `trigger` |
| `match_metadata` | squads, formations, per-team `press_intensity` and `directness` |
| `kick_off`, `period_end`, `full_time` | clock and score markers |

Pitch is 105 × 68 m. Coordinates are always from the perspective of the team in
possession attacking towards `x = 105`, which makes every downstream metric
direction-agnostic.

### Realism

Calibrated so the output passes a football sanity check. Across four seeds:

| Metric | This generator | Real-world range |
|---|---|---|
| Events per match | 2,500–2,600 | ~2,000–3,000 |
| Pass accuracy | 74–77% | ~75–85% |
| Shots per match | 19–26 | ~20–28 |
| Total xG | 0.9–1.9 | ~1.0–3.5 |

Teams carry tactical dials (`press_intensity`, `directness`) and the match runs
a drifting momentum variable, so possession swings have shape rather than being
uniform noise.

## What the analysis layer produces

`src/analyze.py` is dependency-free and returns plain dicts, so the same code
runs in a notebook, an Azure Function, or a Container App worker.

- **Team stats** — passing volume and accuracy, average pass difficulty,
  progressive passes, shots, xG and xG/shot, final-third touches, defensive
  actions, average pressure applied.
- **Possession share** and **field tilt** (share of final-third touches — the
  standard proxy for territorial control, and usually more honest than raw
  possession).
- **Player stats** — touches, pass accuracy, progressive passes, carry distance,
  top speed, xG, defensive actions.
- **Momentum timeline** — five-minute windows with possession split, xG created,
  tempo (actions/min), turnover rate, mean pressure and pressure volatility.
- **Match state** — each window labelled `controlled`, `contested` or `chaotic`.
  Thresholds are relative to the match's own median, not absolute, because a
  high-press game has a higher baseline turnover rate throughout and absolute
  cut-offs would label every window the same way.
- **Key moments** — events ranked by importance, so the narrative layer has
  something worth explaining rather than a flat log. Goals rank categorically
  above build-up play, and an improbable (low-xG) goal outranks a tap-in.

## Roadmap

1. **Narrative agent** — turn ranked key moments and match state into
   commentary, with the explanation attached to the data that justifies it.
2. **Multi-agent orchestration** — distinct eventing, analyst, narrator and
   personalization agents with real handoffs over shared match state.
3. **Render layer** — timed, machine-readable output suitable for synchronized
   graphical overlays on a live feed.
4. **Personalization** — analyst vs casual modes, favourite club and player
   focus, single-metric viewing modes, multi-language output.
